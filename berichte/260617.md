  ## 2 Grundlagen: Zeichenkodierung und Binärdarstellung

  Computer kennen nur Zahlen (Bits und Bytes). Um Text zu speichern, wird jedes Zeichen einer Zahl zugeordnet – das nennt man **Zeichenkodierung**. Die wichtigsten Kodierungen sind:

  - **ASCII:** Nur 128 Zeichen (englische Buchstaben, Ziffern, Sonderzeichen), 1 Byte pro Zeichen.
  - **Latin-1 / ISO-8859-1:** Erweiterung auf 256 Zeichen, deckt westeuropäische Sprachen ab (ä, ö, ü, ß).
  - **CP-1252 (ANSI):** Ähnlich wie Latin-1, aber mit druckbaren Zeichen im Bereich `0x80`–`0x9F` (z. B. `€`).
  - **UTF-8:** Moderner Standard. Kann alle Unicode-Zeichen (inkl. Emojis) darstellen. Kompatibel mit ASCII für die ersten 128 Zeichen. Zeichen außerhalb von ASCII werden mit 2–4 Bytes kodiert.

  Werkzeuge zur Analyse von Binär- und Textdaten:

  - **`xxd`:** Erstellt einen Hex-Dump einer Datei (hexadezimale und ASCII-Darstellung).
  - **`hexdump`:** Ähnlich wie `xxd`, mit anderen Optionen und Darstellungsmöglichkeiten.
  - **`od`:** „Octal Dump" – zeigt Daten in verschiedenen Formaten (oktal, hex, dezimal).
  - **`iconv`:** Konvertiert Dateien von einer Zeichenkodierung in eine andere.
  - **`file`:** Erkennt den Typ und die Kodierung einer Datei.
  - **`gcc`:** C-Compiler unter Linux zum Übersetzen und Ausführen eigener Programme.

  ### Übung 1: UTF-8-Kodierung ermitteln

  **Aufgabe:** Die UTF-8-Kodierung der Zeichen `🥳😎👽©€ß` ermitteln.

  **Schritt 1 – Hex-Dump mit `xxd`:**

  ```bash
  printf '🥳😎👽©€ß' | xxd
  ```

  **Ergebnis (Auszug):**

  ```
  00000000: f09f a5b3 f09f 988e f09f 91bd c2a9 e282  ................
  00000010: acc3 9f                                   ...
  ```

  **Schritt 2 – Gleiche Ausgabe mit einem C-Programm:**

  ```c
  #include <stdio.h>

  int main() {
      // UTF-8 kodierte Bytes der Zeichen 🥳 😎 👽 © € ß
      unsigned char bytes[] = {
          0xF0, 0x9F, 0xA5, 0xB3,  // 🥳
          0xF0, 0x9F, 0x98, 0x8E,  // 😎
          0xF0, 0x9F, 0x91, 0xBD,  // 👽
          0xC2, 0xA9,              // ©
          0xE2, 0x82, 0xAC,        // €
          0xC3, 0x9F               // ß
      };
      int len = sizeof(bytes);

      // Hex-Dump ausgeben
      for (int i = 0; i < len; i++) {
          printf("%02X ", bytes[i]);
          if ((i + 1) % 8 == 0) printf("\n");
      }
      printf("\n");

      // Zeichen direkt ausgeben (Terminal muss UTF-8 unterstützen)
      fwrite(bytes, 1, len, stdout);
      printf("\n");

      return 0;
  }
  ```

  **Kompilieren und ausführen:**

  ```bash
  gcc -o utf8_demo utf8_demo.c
  ./utf8_demo
  ```

  **Erklärung:**

  UTF-8 kodiert Zeichen außerhalb von ASCII mit mehreren Bytes. Die Bytes lassen sich so zuordnen:

  | Zeichen | UTF-8 (hex)       | Anzahl Bytes |
  |---------|-------------------|--------------|
  | 🥳      | `F0 9F A5 B3`     | 4            |
  | 😎      | `F0 9F 98 8E`     | 4            |
  | 👽      | `F0 9F 91 BD`     | 4            |
  | ©       | `C2 A9`           | 2            |
  | €       | `E2 82 AC`        | 3            |
  | ß       | `C3 9F`           | 2            |

  Emojis benötigen 4 Bytes, da sie sehr hohe Unicode-Codepunkte haben. Einfachere Sonderzeichen wie `©` oder `ß` kommen mit 2–3 Bytes aus.

  ### Übung 2: Hex Dump – Binärdarstellung und Zusatzfragen

  #### 2a: Binärausgabe (0 und 1) mit einem C-Programm

  `xxd` und `hexdump` geben standardmäßig hexadezimal aus, nicht binär. Mit einem eigenen C-Programm lässt sich jedes Byte als 8 Bits (0 und 1) darstellen:

  ```c
  #include <stdio.h>

  // Gibt ein einzelnes Byte als 8 Bits aus
  void print_binary(unsigned char byte) {
      for (int i = 7; i >= 0; i--) {
          printf("%d", (byte >> i) & 1);
      }
  }

  int main() {
      unsigned char text[] = "A";  // ASCII 'A' = 0x41 = 01000001

      printf("Zeichen: %c\n", text[0]);
      printf("Hex:     0x%02X\n", text[0]);
      printf("Binaer:  ");
      print_binary(text[0]);
      printf("\n");

      return 0;
  }
  ```

  **Ausgabe:**

  ```
  Zeichen: A
  Hex:     0x41
  Binaer:  01000001
  ```

  **Erklärung des Bit-Shifts:** `(byte >> i) & 1` schiebt das Byte um `i` Stellen nach rechts und maskiert das unterste Bit – so wird jedes Bit einzeln ausgelesen.

  #### 2b: Was bedeutet „Octet"?

  Ein **Octet** ist ein Byte bestehend aus genau 8 Bit. Der Begriff wird vor allem in der **Netzwerktechnik** (z. B. in RFCs) verwendet, weil das Wort „Byte" historisch nicht immer 8 Bit bedeutet hat (es gab früher Systeme mit 6- oder 9-Bit-Bytes). Mit „Octet" ist immer eindeutig klar: genau 8 Bit. In C entspricht das dem Typ `unsigned char`.

  #### 2c: Die `-E` Option von `xxd`

  ```bash
  xxd -E datei.txt
  ```

  Die Option `-E` schaltet die rechte Spalte (die ASCII-Darstellung) auf **EBCDIC**-Kodierung um. EBCDIC ist ein älteres Zeichenkodierungssystem von IBM, das auf Großrechnern (Mainframes) verwendet wurde. Heutzutage ist diese Option kaum noch relevant, da EBCDIC fast vollständig durch ASCII/UTF-8 verdrängt wurde.

  #### 2d: Dezimalwert als Binärdatei schreiben und zurücklesen

  **Mit `printf` und `xxd` (Kommandozeile):**

  ```bash
  value=65534
  printf "%.8x" $value | xxd -r -p > data.bin
  od -An -t u4 --endian=big data.bin
  ```

  **Dasselbe mit einem C-Programm:**

  ```c
  #include <stdio.h>
  #include <stdint.h>

  int main() {
      uint32_t value = 65534;

      // Schreiben: als Big-Endian Bytes in Datei speichern
      FILE *fp = fopen("data.bin", "wb");
      unsigned char bytes[4];
      bytes[0] = (value >> 24) & 0xFF;
      bytes[1] = (value >> 16) & 0xFF;
      bytes[2] = (value >>  8) & 0xFF;
      bytes[3] = (value >>  0) & 0xFF;
      fwrite(bytes, 1, 4, fp);
      fclose(fp);

      // Lesen: Bytes aus Datei als Big-Endian Integer zurücklesen
      fp = fopen("data.bin", "rb");
      fread(bytes, 1, 4, fp);
      fclose(fp);

      uint32_t result = ((uint32_t)bytes[0] << 24) |
                        ((uint32_t)bytes[1] << 16) |
                        ((uint32_t)bytes[2] <<  8) |
                        ((uint32_t)bytes[3]);

      printf("Geschriebener Wert: %u\n", value);
      printf("Gelesener Wert:     %u\n", result);
      printf("Hex-Bytes: %02X %02X %02X %02X\n",
             bytes[0], bytes[1], bytes[2], bytes[3]);

      return 0;
  }
  ```

  **Ausgabe:**

  ```
  Geschriebener Wert: 65534
  Gelesener Wert:     65534
  Hex-Bytes: 00 00 FF FE
  ```

  **Erklärung:** Big-Endian bedeutet, das höchste Byte kommt zuerst. Der Bit-Shift `>> 24` holt das oberste Byte, `>> 16` das zweite usw. `& 0xFF` stellt sicher, dass nur das unterste Byte übrig bleibt.

  #### 2e: Die `-i` Option von `xxd`

  ```bash
  xxd -i data.bin
  ```

  Die Option `-i` gibt den Dateiinhalt als **C-Array** aus – also direkt als Code, den man in ein C-Programm einfügen kann:

  ```c
  unsigned char data_bin[] = {
    0x00, 0x00, 0xff, 0xfe
  };
  unsigned int data_bin_len = 4;
  ```

  **Mögliche Anwendung:** Wenn man z. B. eine kleine Binärdatei (Icon, Firmware-Patch) direkt in ein C-Programm einbetten möchte, ohne sie als externe Datei mitzuliefern. Das generierte Array kann man direkt in den Quellcode kopieren.

  ### Übung 3: Windows Editor – Unterschiede UTF-8 vs. ANSI

  **Aufgabe:** Eine Textdatei mit Windows-Editor in UTF-8 und ANSI speichern, in die Linux-Shell importieren und vergleichen.

  #### Schritt 1: Datei mit `cat` anzeigen

  ```bash
  cat datei_utf8.txt
  cat datei_ansi.txt
  ```

  **Unterschied:**

  - Die UTF-8-Datei wird korrekt angezeigt (ä, ö, ü, ß, € erscheinen richtig), weil die Linux-Kommandozeile standardmäßig UTF-8 verwendet.
  - Die ANSI-Datei zeigt Sonderzeichen als **Kauderwelsch** (z. B. `Ã¶` statt `ö`), weil CP-1252 und UTF-8 dieselben Sonderzeichen anders kodieren.

  #### Schritt 2: Hexdump-Vergleich

  ```bash
  xxd datei_utf8.txt
  xxd datei_ansi.txt
  ```

  **Kodierung der Buchstaben Ö, ß und € im Vergleich:**

  | Zeichen | UTF-8 (hex)   | CP-1252 / ANSI (hex) |
  |---------|---------------|----------------------|
  | Ö       | `C3 96`       | `D6`                 |
  | ß       | `C3 9F`       | `DF`                 |
  | €       | `E2 82 AC`    | `80`                 |

  In UTF-8 brauchen Sonderzeichen 2–3 Bytes, in CP-1252 immer genau 1 Byte.

  #### Schritt 3: Zeilenenden analysieren

  ```bash
  xxd datei_windows.txt | head
  xxd datei_linux.txt | head
  ```

  **Unterschied:**

  - **Windows:** Zeilenende = `0D 0A` (Carriage Return + Line Feed, auch `\r\n`)
  - **Linux:** Zeilenende = `0A` (nur Line Feed, auch `\n`)

  Das `\r` ist ein Überbleibsel aus der Schreibmaschinen-Ära. Es kann unter Linux zu Problemen führen (z. B. Skripte laufen nicht korrekt). Im Hexdump sieht man es als `0d` direkt vor dem `0a`.

  #### Schritt 4: Konvertierung mit `iconv`

  ```bash
  iconv -f cp1252 -t utf-8 datei_ansi.txt > datei_konvertiert.txt
  cat datei_konvertiert.txt
  ```

  **Dasselbe mit einem C-Programm (vereinfacht für ß und Ö):**

  ```c
  #include <stdio.h>

  // Vereinfachte CP-1252 zu UTF-8 Konvertierung für häufige deutsche Zeichen
  void cp1252_byte_to_utf8(unsigned char c, FILE *out) {
      if (c < 0x80) {
          // ASCII-Bereich: 1:1 übernehmen
          fputc(c, out);
      } else if (c == 0x80) {
          // € in CP-1252 → E2 82 AC in UTF-8
          fputc(0xE2, out); fputc(0x82, out); fputc(0xAC, out);
      } else if (c >= 0xC0) {
          // Latin-Bereich: CP-1252 → UTF-8 (2-Byte-Sequenz)
          fputc(0xC0 | (c >> 6), out);
          fputc(0x80 | (c & 0x3F), out);
      } else {
          fputc(c, out);  // Rest unverändert
      }
  }

  int main() {
      FILE *in  = fopen("datei_ansi.txt", "rb");
      FILE *out = fopen("datei_konvertiert.txt", "wb");
      int c;
      while ((c = fgetc(in)) != EOF) {
          cp1252_byte_to_utf8((unsigned char)c, out);
      }
      fclose(in);
      fclose(out);
      printf("Konvertierung abgeschlossen.\n");
      return 0;
  }
  ```

  **Ergebnis:** Die konvertierte Datei zeigt alle Sonderzeichen korrekt an, weil die CP-1252-Bytes korrekt in UTF-8 übersetzt werden.

  #### Schritt 5: Unterschied ANSI und Latin-1

  **ANSI (CP-1252)** und **Latin-1 (ISO-8859-1)** sind fast identisch, unterscheiden sich aber im Bereich der Bytes `0x80`–`0x9F`:

  - In **Latin-1** sind diese Bytes reservierte Steuerzeichen (nicht druckbar).
  - In **CP-1252** (Windows-Standard) sind hier druckbare Zeichen definiert, z. B. `€` = `0x80`, `„` = `0x84`, `…` = `0x85`.

  Das bedeutet: Eine als „ANSI" gespeicherte Windows-Datei ist **nicht dasselbe wie Latin-1**, auch wenn beide oft verwechselt werden.

  ### Challenge: JPEG/Exif-Daten analysieren

  **Aufgabe:** Die Struktur der Exif-Daten in einer JPEG-Datei verstehen und auslesen.

  JPEG-Dateien beginnen immer mit den Bytes `FF D8` (SOI = Start of Image). Exif-Daten folgen direkt danach im APP1-Segment (`FF E1`).

  **Schritt 1 – Hex-Dump der ersten Bytes mit `xxd`:**

  ```bash
  xxd htl_logo.jpg | head -20
  ```

  **Schritt 2 – Exif-Header mit einem C-Programm auslesen:**

  ```c
  #include <stdio.h>
  #include <string.h>

  int main() {
      FILE *fp = fopen("htl_logo.jpg", "rb");
      if (!fp) { printf("Datei nicht gefunden.\n"); return 1; }

      unsigned char buf[32];
      fread(buf, 1, 32, fp);

      // JPEG-Signatur prüfen: muss mit FF D8 beginnen
      if (buf[0] == 0xFF && buf[1] == 0xD8) {
          printf("Gültige JPEG-Datei erkannt (FF D8).\n");
      } else {
          printf("Keine JPEG-Datei.\n");
          fclose(fp);
          return 1;
      }

      // APP1-Segment prüfen (Exif): FF E1
      if (buf[2] == 0xFF && buf[3] == 0xE1) {
          int app1_len = (buf[4] << 8) | buf[5];
          printf("APP1-Segment gefunden (FF E1), Länge: %d Bytes\n", app1_len);

          // Exif-Kennung prüfen
          if (memcmp(buf + 6, "Exif", 4) == 0) {
              printf("Exif-Daten vorhanden.\n");
          }
      } else {
          printf("Kein APP1/Exif-Segment direkt nach SOI.\n");
      }

      // Ersten 16 Bytes als Hex ausgeben
      printf("\nErste 16 Bytes:\n");
      for (int i = 0; i < 16; i++) {
          printf("%02X ", buf[i]);
      }
      printf("\n");

      fclose(fp);
      return 0;
  }
  ```

  **Kompilieren und ausführen:**

  ```bash
  gcc -o exif_reader exif_reader.c
  ./exif_reader
  ```

  **Typische Exif-Felder:**

  | Feld              | Bedeutung                      |
  |-------------------|--------------------------------|
  | `Make`            | Hersteller der Kamera          |
  | `Model`           | Kameramodell                   |
  | `DateTime`        | Aufnahmedatum und -uhrzeit     |
  | `GPSLatitude`     | GPS-Breitengrad                |
  | `GPSLongitude`    | GPS-Längengrad                 |
  | `FNumber`         | Blende (z. B. f/2.8)          |
  | `ISOSpeedRatings` | ISO-Wert                       |

  Die Exif-Struktur basiert auf dem **TIFF-Format**: Es gibt sogenannte **IFDs (Image File Directories)**, die jeweils Tags mit Werten speichern. Jeder Tag hat eine 2-Byte-ID, einen Datentyp und einen Wert – all das lässt sich in C direkt aus den Rohdaten der Datei lesen.

  ## 4 Zusammenfassung

  In dieser Übung wurden die Grundlagen der Zeichenkodierung und der Binärdarstellung unter Linux erarbeitet. Die wichtigsten Erkenntnisse:

  - **UTF-8** ist der heutige Standard und kann alle Unicode-Zeichen darstellen; Sonderzeichen benötigen 2–4 Bytes.
  - **CP-1252 (ANSI)** und **Latin-1** sind ähnlich, unterscheiden sich aber im Bereich `0x80`–`0x9F` – CP-1252 belegt diese Stellen mit druckbaren Zeichen (z. B. `€`).
  - **Windows** verwendet `\r\n` als Zeilenende, **Linux** nur `\n` – das kann bei Skripten zu Fehlern führen.
  - `xxd` und `hexdump` ermöglichen die direkte Analyse von Dateien auf Byte-Ebene.
  - Mit `iconv` lassen sich Dateien einfach zwischen Kodierungen konvertieren.
  - **C-Programme** ermöglichen eine exakte Kontrolle über jeden einzelnen Byte – mit `fread`, `fwrite`, Bit-Shifts und Masken lassen sich alle genannten Aufgaben auch ohne externe Tools lösen.
  - JPEG-Dateien enthalten im Exif-Format strukturierte Metadaten, deren Header-Struktur direkt mit C und `fread` ausgelesen werden kann.

  Allgemein gilt: Das Verständnis von Zeichenkodierungen ist essenziell, um Probleme mit Sonderzeichen, kaputten Umlauten oder nicht funktionierenden Skripten zu vermeiden.
